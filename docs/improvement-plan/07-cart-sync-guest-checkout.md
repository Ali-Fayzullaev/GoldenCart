# Шаг 7: Корзина не синхронизируется между устройствами, нет гостевого чекаута

## Проблема

`lib/store/cart-store.ts` — корзина хранится только в `localStorage`
(`zustand/persist`, ключ `goldencart-cart`). Это значит:

- Покупатель, открывший магазин с телефона и потом с компьютера, увидит
  две разные пустые корзины.
- Чтобы вообще оформить заказ, нужно быть залогиненным (`use-orders.ts:66` —
  `if (!session?.user) throw new Error("Не авторизован")`) — гостевого
  чекаута нет в принципе.

При этом часть пользовательских данных (wishlist, сохранённые адреса) **уже**
синхронизируются через БД (`useWishlist`, `useCustomerAddresses`) — то есть в
проекте уже есть паттерн для server-synced пользовательских данных, просто
корзина из него выпала. Это несогласованность: пользователь логично ожидает,
что раз избранное синхронизируется между устройствами, то и корзина тоже.

## Почему это важно

Для e-commerce брошенная корзина из-за смены устройства — прямая потеря
выручки продавца. А обязательная регистрация перед покупкой — известный
фактор отказа от покупки (часть покупателей уходит, не желая регистрироваться
ради разовой покупки).

## Что сделать

Два независимых направления, можно делать по отдельности:

### 7.1 Серверная синхронизация корзины (для залогиненных)

1. Добавить таблицу `cart_items` (она, судя по `001_initial.sql:13`, даже
   была в дропнутом наброске схемы — `DROP TABLE IF EXISTS cart_items`,
   то есть когда-то планировалась) с `customer_id`, `store_id`, `product_id`,
   `variant_label`, `quantity`.
2. При логине — смержить локальную (`localStorage`) корзину с серверной
   (например, серверная корзина — источник истины, локальные позиции
   добавляются поверх).
2. `cart-store.ts` продолжает быть локальным кэшем для гостей и для
   мгновенного отклика UI, но для залогиненных синхронизируется с сервером
   (можно через react-query mutation на каждое изменение, дебounced).

### 7.2 Гостевой чекаут

1. В `checkout/page.tsx` разрешить оформление заказа без сессии Supabase —
   собирать имя/телефон/адрес прямо в форме (уже есть форма для этого), и
   создавать `orders.customer_id = NULL` (потребует миграции — сделать
   `customer_id` nullable и добавить `guest_phone`/`guest_name` поля) либо
   создавать "теневой" профиль по номеру телефона.
2. Обновить RLS-политики на `orders`/`order_items`, чтобы гостевые заказы
   не были видны другим покупателям (продавец видит все заказы своего
   магазина — это уже так).

## Критерий готовности (DoD)

- [ ] Покупатель добавляет товар в корзину на телефоне, логинится на
      компьютере — товар виден в корзине.
- [ ] Покупатель без аккаунта может дойти до оформления заказа и оставить
      контактные данные, не регистрируясь (если бизнес решит, что это нужно —
      пункт 7.2 можно вынести в отдельное решение, не блокирующее 7.1).
- [ ] RLS-политики не позволяют покупателю А видеть гостевые заказы
      покупателя Б.
