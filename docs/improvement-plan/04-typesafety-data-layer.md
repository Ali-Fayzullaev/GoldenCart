# Шаг 4: Убрать `as unknown as Type` из data-слоя

## Проблема

Во всех хуках в `lib/hooks/` (более 40 мест: `use-orders.ts:19,43,91,114,144`,
`use-products.ts:22,44,79,137,169`, `use-stores.ts:26,44,77,99,124` и т.д.)
результат запроса Supabase приводится через двойное приведение:

```ts
return data as unknown as Product[];
```

`as unknown as T` — это способ сказать TypeScript "не проверяй меня вообще".
Supabase-клиент при правильно сгенерированных типах БД (`supabase gen types
typescript`) и так возвращает корректно типизированные данные — двойное
приведение здесь означает, что:

- типы `lib/types/database.ts`, скорее всего, написаны вручную и разошлись
  со схемой (иначе двойное приведение не понадобилось бы),
  Supabase-клиент создаётся без generic-типа `Database`, поэтому `.from()`
  возвращает `any`/`unknown`, и типизация — чистая иллюзия для разработчика.
- любая опечатка в названии колонки или несовпадение типа (например,
  `card_style` забыли в типе `StoreSettings`) не будет поймана компилятором —
  упадёт только в рантайме.

## Почему это важно

Это снижает главную ценность TypeScript — отлов ошибок до рантайма. Учитывая,
что в проекте уже есть хрупкие места (например, баг с вариантами из шага 1),
типобезопасность данных — это первая линия защиты от подобных багов в
будущем.

## Что сделать

1. Сгенерировать актуальные типы из реальной схемы Supabase:
   ```bash
   npx supabase gen types typescript --project-id <id> > lib/types/database-generated.ts
   ```
   (или `--local`, если есть локальный стек).
2. Создать клиент с типом `Database`:
   ```ts
   // lib/supabase/client.ts
   import type { Database } from "@/lib/types/database-generated";
   export function createClient() {
     return createBrowserClient<Database>(url, key);
   }
   ```
   То же для `lib/supabase/server.ts`.
3. После этого `.from("products").select(...)` начнёт возвращать реальные
   типы — убрать `as unknown as Type` по одному хуку за раз, давая
   компилятору показать реальные расхождения.
4. Там, где `select(...)` выбирает не все колонки (как `PRODUCT_COLUMNS` в
   `use-products.ts`), использовать generic-параметр Supabase
   (`.returns<Product[]>()`) вместо приведения типов после получения данных.
5. Сверить вручную написанные типы в `lib/types/database.ts` с
   сгенерированными — оставить вручную написанные только там, где это
   осознанные derived-типы (`StoreWithSettings`, `OrderWithItems`), и
   строить их через `&`/`Pick` от сгенерированных, а не дублировать поля.

## Критерий готовности (DoD)

- [ ] Supabase-клиент (browser и server) типизирован через `Database`.
- [ ] Ноль вхождений `as unknown as` в `lib/hooks/*.ts` (проверяется грепом).
- [ ] `tsc --noEmit` проходит без ошибок после удаления приведений.
- [ ] Добавлен npm-скрипт `db:types` для регенерации типов при изменении схемы,
      и шаг "обнови типы" зафиксирован в чек-листе ревью миграций.
