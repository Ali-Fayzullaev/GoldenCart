# Шаг 6: Витрина целиком client-side — нет SEO и медленный первый рендер

## Проблема

`app/store/[slug]/page.tsx` (список товаров) и
`app/store/[slug]/product/[id]/product-client.tsx` (карточка товара) —
полностью `"use client"`-компоненты. Данные о товарах, магазине, рейтингах,
баннерах грузятся через React Query **после** гидратации в браузере.
Server-side используется только для `generateMetadata()` в `layout.tsx`.

Это значит:

- Поисковики и соцсети (превью при шаринге ссылки на товар) видят пустой
  HTML без названия/цены/фото товара в первом ответе сервера (кроме того,
  что попало в метатеги).
- Time-to-content для покупателя на медленном интернете выше, чем могло бы
  быть — нужен полный JS-бандл + клиентский запрос, прежде чем появится
  хоть один товар.
- Для AGENTS.md этого проекта явно указано читать доки нового Next.js перед
  написанием кода — то есть проект целенаправленно на актуальном App Router,
  который как раз заточен под server components для подобных кейсов, но эта
  возможность не используется на самой важной для SEO части (витрина).

## Почему это важно

GoldenCart — мультитенантная SaaS-платформа интернет-магазинов: для каждого
продавца органический трафик из поиска на карточки товаров — это то, ради
чего вообще имеет смысл иметь персональный `/store/[slug]`, а не маркетплейс.
Без SSR/SEO эта часть ценности теряется.

## Что сделать

Двигаться постепенно, не переписывая всё разом:

1. **Карточка товара** (`product/[id]/page.tsx`) — самый высокий приоритет
   для SEO. Перенести первичную загрузку товара (название, цена, фото,
   описание) на сервер: server component делает Supabase-запрос напрямую
   (через `lib/supabase/server.ts`) и рендерит статичный HTML с данными.
   Интерактивные части (выбор варианта, кнопка "в корзину", отзывы) остаются
   маленьким client-компонентом, получающим начальные данные как props —
   а не делающим повторный fetch на клиенте.
2. **Список товаров** (`store/[slug]/page.tsx`) — первая страница (без
   фильтров) рендерится на сервере для SEO и быстрого First Contentful
   Paint; дальнейшая фильтрация/сортировка/инфинит-скролл остаются
   client-side (через react-query), используя серверные данные как
   initialData.
3. Использовать `generateStaticParams`/ISR (`revalidate`) там, где уместно —
   каталоги товаров не меняются ежесекундно, можно кэшировать на несколько
   минут вместо запроса на каждый визит.
4. Проверить, что `generateMetadata()` для карточки товара формирует
   полноценные Open Graph теги (title, description, image, price) — сейчас
   есть только на уровне магазина в `layout.tsx`, не проверено на уровне
   товара.

## Критерий готовности (DoD)

- [ ] `curl` (без выполнения JS) на `/store/[slug]/product/[id]` отдаёт HTML
      с названием, ценой и описанием товара.
- [ ] Open Graph превью карточки товара показывает фото/цену/название при
      шаринге в Telegram/WhatsApp.
- [ ] Lighthouse SEO score для карточки товара и каталога — не ниже 90.
- [ ] Интерактивность (добавление в корзину, выбор варианта) работает как
      раньше, без регрессий.
